### 1.2 Key Data Flows

#### Flow A: Anonymous Guest Progress & Local Storage Sync

```
User Action (e.g. Complete Lesson / Pass Quiz)
  ↓
[LessonPageClient.tsx / QuizClient.tsx]
  ↓ invokes
useProgress() → useProgressMutations()
  ↓ (No authenticated Supabase user detected)
1. appStateMarkLessonComplete() → Updates React AppContext in AppProviders.tsx
2. guestMarkLessonComplete() → Writes to sessionStorage ("hmc_guest_completedLessons")
3. AppProviders.tsx useEffect → Writes to localStorage ("hmc_completed_lessons", "hmc_quiz_scores")
4. ToastProvider displays completion confirmation
```

#### Flow B: Guest-to-Authenticated Account Migration Flow

```
User Submits Login / Signup Form (`LoginForm.tsx` / `SignupForm.tsx`)
  ↓
`supabase.auth.signInWithPassword()` succeeds
  ↓
`migrateGuestProgressToSupabase(supabase, user.id)` reads `sessionStorage`
  ↓
Batched Upserts to Supabase:
  - `lesson_progress` (user_id, lesson_id, completed, completed_at)
  - `quiz_attempts` (user_id, quiz_id, score, max_score, passed)
  ↓
`clearGuestProgress()` clears temporary storage
  ↓
App redirects to `/dashboard` → `useProgress` fetches fresh Supabase dataset
```

#### Flow C: Authenticated Lesson Completion & Side Effects

```
User clicks "Mark as Complete" on `/learn/[slug]`
  ↓
`useProgressMutations.markLessonComplete(lessonId)`
  ↓
1. Optimistic UI update via `completedIdsRef` & `setSupabaseCompletedLessonIds`
2. Supabase DB Write: `supabase.from("lesson_progress").upsert(...)`
3. Side-Effect Handlers (`sideEffects.ts`):
   a. `updateDailyLog(supabase, userId)` → upserts `daily_log` for current UTC date
   b. `updateStreak(supabase, userId)` → recalculates `streaks` (current_streak, longest_streak)
   c. `checkAchievements(supabase, userId, completedLessonIds)` → evaluates criteria
      → inserts new rows to `achievements` table
      → inserts unread notification into `notifications` table
      → triggers celebration Toast (`AchievementToast`)
```

#### Flow D: Static Content Ingestion & Runtime Hydration

```
`content/**/*.mdx` (Source of truth)
  ↓ (npm run prebuild / build)
`scripts/bundle-*.ts` via `gray-matter` & `markdown-it`
  ↓
`src/data/*Bundles.{en,es}.ts` (Type-safe bundled JavaScript objects)
  ↓
`src/lib/*/load*.ts` (Accessor functions)
  ↓
Next.js Static Site Generation (`generateStaticParams` in `[locale]/[slug]/page.tsx`)
  ↓
Pre-rendered static HTML/RSC payloads on Netlify CDN Edge
```

## 2. Bugs & Correctness

### 🔴 CRITICAL: Password Reset Client Only Reads URL Hash, Breaking Modern PKCE Reset Links

- **File & Lines:** `src/app/[locale]/auth/reset-password/ResetPasswordClient.tsx:23-37`
- **Mechanism:** In `@supabase/ssr` and Supabase v2 PKCE flow, password recovery links redirect the user with a query string parameter: `?code=xxxx` (or `?token_hash=xxxx`), NOT a URL hash fragment (`#code=xxxx`). `ResetPasswordClient.tsx` executes:
  ```typescript
  const params = new URLSearchParams(window.location.hash.substring(1));
  const code = params.get("code");
  if (!code) {
    setError(t("errorGeneric"));
    return;
  }
  ```
- **Consequence:** `window.location.hash` is empty on standard email recovery redirects. `code` evaluates to `null`, immediately triggering `setError("An error occurred")`. Real users following password reset emails are completely blocked from resetting their passwords.
- **Fix:** Check `new URLSearchParams(window.location.search).get("code")` first, with fallback to `window.location.hash`.

---

### 🔴 CRITICAL: Supabase Email OTP/Confirmation Token Hash Omission

- **File & Lines:** `src/app/[locale]/auth/confirm/route.ts:15-38`
- **Mechanism:** Standard Supabase email templates for signup confirmation use `{{ .ConfirmationURL }}`, which supplies `token_hash` and `type=email` (or `type=signup`). `src/app/[locale]/auth/confirm/route.ts` only extracts `const code = searchParams.get("code")` and calls `supabase.auth.exchangeCodeForSession(code)`.
- **Consequence:** If an email confirmation link containing `token_hash` is clicked, `code` is null and the route redirects to `/${locale}/auth/login?error=confirmation_failed`.
- **Fix:** Support both PKCE `code` and `verifyOtp({ token_hash, type: type as EmailOtpType })`.

### 🟡 SHOULD-FIX: Guest Progress Multi-Tab / Session Storage Disconnect on Migration

- **File & Lines:** `src/lib/guestProgress.ts:6-21, 70-89` vs `src/components/AppProviders.tsx:110-124`
- **Mechanism:** `guestProgress.ts` writes guest lesson completions to `sessionStorage` (`hmc_guest_completedLessons`), whereas `AppProviders.tsx` writes state to `localStorage` (`hmc_completed_lessons`).
- **Consequence:** If a guest finishes 5 lessons, closes their browser tab, re-opens the site tomorrow, and signs up, `sessionStorage` was wiped on tab close. `migrateGuestProgressToSupabase` finds 0 items to migrate, even though `localStorage` still holds the completed lesson IDs in `AppProviders`. The user's historical guest progress is lost upon registration.
- **Fix:** Have `guestProgress.ts` fall back to `localStorage` when `sessionStorage` is empty, or unify storage key references.

---

### 🟡 SHOULD-FIX: Race Condition in Parallel Progress Fetching vs Guest Migration on Mount

- **File & Lines:** `src/hooks/useProgress.ts:46-61`, `src/hooks/useProgress/guestMigration.ts:14-32`, `src/hooks/useProgress/supabaseProgress.ts:26-63`
- **Mechanism:** When a user logs in, `useGuestMigration` triggers `migrateGuestProgressToSupabase` asynchronously. In parallel, `useSupabaseProgress` immediately executes `fetchProgress()` against the database.
- **Consequence:** If `fetchProgress()` resolves before `migrateGuestProgressToSupabase` completes its network upsert, the in-memory `supabaseCompletedLessonIds` will remain empty until the user triggers another mutation or hard-refreshes the page.
- **Fix:** Have `useGuestMigration` invoke a callback or return a trigger to `useSupabaseProgress` upon successful migration completion.

---

### 🟡 SHOULD-FIX: Auth Failure Callback Hardcodes Default Locale Redirect

- **File & Lines:** `src/app/[locale]/auth/callback/route.ts:11, 37` and `src/app/[locale]/auth/confirm/route.ts:13, 40`
- **Mechanism:**
  ```typescript
  return NextResponse.redirect(new URL("/auth/login?error=auth_failed", request.url));
  ```
  Because `next-intl` uses `localePrefix: "always"`, hitting `/auth/login` without a locale prefix triggers a 307 redirect through middleware to `/en/auth/login`.
- **Consequence:** Spanish users on `/es/auth/...` experiencing an auth error or rate limit are forced into English `/en/auth/login`.
- **Fix:** Construct redirect URL as `/${locale}/auth/login?error=auth_failed`.

---

### 🟡 SHOULD-FIX: Visit Planner Tool Persists Raw Locale-Specific Strings in Storage

- **File & Lines:** `src/app/[locale]/tools/visit-planner/useVisitPlanner.ts:28-32, 108-115`
- **Mechanism:** `useVisitPlanner` stores `selectedQuestions` as raw localized text strings (e.g. `"When did this symptom start?"`) in `localStorage` under key `hmc_visit_planner`.
- **Consequence:** When a user toggles language from English to Spanish, the saved planner rehydrates with English question strings into the Spanish UI, resulting in mixed-language artifacts on print and review.
- **Fix:** Persist question ID keys (e.g., `"q_new_symptom_start"`) and resolve localized text dynamically during render.

## 3. Security

### 🔴 CRITICAL: Missing `SUPABASE_SERVICE_ROLE_KEY` Build-Time Verification Gate

- **File & Lines:** `scripts/check-production-env.mjs:31-52` vs `src/app/api/contact/route.ts:130-135`
- **Mechanism:** Migration `013_secure_contact_submissions.sql` strictly dropped public inserts on `contact_submissions`. `src/app/api/contact/route.ts` requires `process.env.SUPABASE_SERVICE_ROLE_KEY` to insert submissions. However, `scripts/check-production-env.mjs` only verifies `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
- **Consequence:** If a Netlify deployment is configured without `SUPABASE_SERVICE_ROLE_KEY`, the production build succeeds without error, but all contact form submissions from the public immediately fail with HTTP 503 "Service unavailable".
- **Fix:** Add `process.env.SUPABASE_SERVICE_ROLE_KEY` to `scripts/check-production-env.mjs`.

---

### 🟡 SHOULD-FIX: Netlify Security Headers vs Next.js Config Header Drift

- **File & Lines:** `next.config.mjs:38-79` vs `netlify.toml:57-70`
- **Mechanism:** Both `next.config.mjs` and `netlify.toml` declare `Content-Security-Policy`, `Strict-Transport-Security`, and `Permissions-Policy`.
  In `netlify.toml:69`, CSP specifies:
  `connect-src 'self' https://*.supabase.co wss://*.supabase.co https://*.ingest.sentry.io https://www.google-analytics.com ...`
  If environment-specific domains (such as custom Sentry ingestion subdomains or Upstash Redis endpoints) are added to `next.config.mjs` without updating `netlify.toml`, Netlify's CDN edge headers override Next.js server headers on static routes.
- **Fix:** Maintain a single canonical header definitions module or script that synchronizes `netlify.toml` and `next.config.mjs`.

---

### 🟡 SHOULD-FIX: JSON-LD Structured Data Script Sanitization

- **File & Lines:** `src/components/JsonLd.tsx:8-25`
- **Mechanism:** `JsonLd` sanitizes serialized JSON strings via regex replacement of `<`, `>`, `/`, `\u2028`, `\u2029`. While effective, it renders raw sanitized strings as direct children of `<Script id={id} type="application/ld+json">`.
- **Consequence:** Next.js `<Script>` components with `type="application/ld+json"` render synchronously into `<head>`. If malformed non-serializable objects or nested `</script>` tags survive edge cases, browser parsers could misinterpret script boundaries.
- **Fix:** Validate input data against `zod` schema or enforce strict `JSON.stringify` serialization.

---

### 🟢 NICE-TO-HAVE: CSRF Origin Verification on Localhost Subdomains

- **File & Lines:** `src/app/api/contact/route.ts:25-61`
- **Mechanism:** `isAllowedOrigin` permits requests where hostname is `localhost` or `127.0.0.1`.
- **Consequence:** Secure in production; during local development, any local port can post to the API route.
- **Fix:** Validate exact port match in non-production environments.

## 4. Performance

### 🔴 CRITICAL: Massive Client Bundle Bloat via Eager Multi-Locale Static Bundling

- **File & Lines:** `src/data/lessonBundles.ts:6-9`, `src/data/quizBundles.ts:6-9`, `src/lib/lessons/loadLessons.ts:1-11`
- **Mechanism:** `lessonBundles.ts` statically imports both `lessonBundles.en.ts` (~246 KB) and `lessonBundles.es.ts` (~268 KB) and exports `{ en, es }`.
  `quizBundles.ts` similarly imports both `quizBundles.en.ts` (~166 KB) and `quizBundles.es.ts` (~181 KB).
- **Consequence:** Whenever any client component (e.g. Dashboard, Lesson page, Search modal) imports lesson or quiz helper functions, webpack bundles **both English and Spanish content (~860 KB of raw JavaScript)** into the initial client bundle. An English-only reader on mobile 3G is forced to download, parse, and evaluate hundreds of kilobytes of Spanish MDX ASTs.
- **Fix:** Refactor `loadLessons.ts` and `loadQuizzes.ts` to use dynamic imports per locale (`import("@/data/lessonBundles." + locale)`), mirroring the pattern in `src/lib/articles/loadArticles.ts:13-26`.

---

### 🟡 SHOULD-FIX: Unnecessary Global Context Re-Renders in `AppProviders`

- **File & Lines:** `src/components/AppProviders.tsx:24-43, 180-234`
- **Mechanism:** `AppProviders` bundles theme, textSize, simpleMode, completedLessons, recentLessons, startedPaths, and quizScores into a single monolithic `AppContextValue`.
- **Consequence:** When a user toggles a single lesson complete, the entire `completedLessons` Set changes reference. Every consumer of `useAppState()` (including Header navigation, search buttons, language toggles, and layout elements) re-renders, even if they only depend on `theme` or `locale`.
- **Fix:** Split `AppProviders` into separate contexts: `PreferencesContext` (theme, text size, simple mode) and `ProgressContext` (completed lessons, scores).

---

### 🟡 SHOULD-FIX: N+1 Secondary Query Waterfall in Paginated Progress Views

- **File & Lines:** `src/lib/dashboard/progress.ts:87-113`
- **Mechanism:** `getCompletedLessonsPaginated` executes a primary paginated query on `lesson_progress`, extracts the lesson IDs, and then executes a secondary `.in("quiz_id", pageQuizIds)` query on `quiz_attempts`.
- **Consequence:** While paged at 10 items, every page transition requires sequential roundtrips to Supabase REST endpoints instead of a single joined query or view.
- **Fix:** Create a Postgres database view or join query in Supabase combining lesson progress with maximum quiz scores.

---

- **UI:** `handleReset` clears `recordedRef` (`QuizClient.tsx:94-101`) so retake calls `saveQuizAttempt` again (`QuizClient.tsx:118-122`).
- **Prod today:** no unique → every retake inserts another row. `getUserProgressSummary` (`progress.ts:37-52`) **sums every row** into `totalQuizzesPassed` / `averageQuizScore` / `totalQuizzesAttempted` — retakes inflate stats. `useSupabaseProgress` keeps best score only (`supabaseProgress.ts:47-54`) so the lesson UI and dashboard **disagree**.
- **After applying current repo `003`:** retake `insert` → unique violation → toast `quizSaveError` (`mutations.ts:92-93`) **with no optimistic rollback** (unlike lessons at `mutations.ts:51-55`). Tests document no revert (`mutations.test.ts:352`).
- **Fix:** upsert on `(user_id, quiz_id)` keeping max score **or** drop unique and treat attempts as history everywhere. Do not apply repo unique blindly onto prod.

#### 🔴 ADV-02 — Side effects are not a transaction; streak achievements never fire

`handleLessonCompletionSideEffects` (`sideEffects.ts:21-36`): `updateDailyLog` → `checkAndAwardAchievements` (only `totalLessonsCompleted`) → `updateStreak`. No wrapping RPC. Order is wrong for streak badges.

`checkAndAwardAchievements` conditions (`achievements.ts:106-129`) include `currentStreak`, `pathCompleted`, `totalBeginnerLessons*`, `glossaryTermsLookedUp`. **Callers never pass those fields.** Dead achievements: `three-day-streak`, `seven-day-streak`, `first-path-complete`, `all-beginner`, `glossary-reader`. `updateStreak` return value is discarded (`sideEffects.ts:36`, `:97`).

`updateStreak` itself is read-modify-write in JS (`.select().single()` then `.upsert`, `streaks.ts:29-93`). Two parallel completions can lose an increment. First audit's historical F-016 is **not** actually atomic in current code.

If `updateStreak` throws after lesson upsert succeeded (`sideEffects.ts:36` awaited from `mutations.ts:57`), `markLessonComplete` rejects with lesson already committed — toast depends on caller. Daily log errors are swallowed (`dailyLog.ts:9`).

#### 🟡 ADV-03 — Guest migration: no `.catch`, no refetch, dual storage

- `useGuestMigration` (`guestMigration.ts:19-22`): `.then` only. Thrown migrate → unhandled rejection; `isMigrationLoading` can stick true.
- Parallel `fetchProgress` (`supabaseProgress.ts:34-37`) vs migrate upserts — **agree with first-audit BUG-04**; still unfixed.
- Guest writes `sessionStorage` (`guestProgress.ts:6-8,40-45`); AppProviders writes `localStorage` (`AppProviders.tsx:110`). **Agree with BUG-03.** Close tab → migrate finds nothing.
- `clearGuestProgress` only if `errors.length === 0` (`guestProgress.ts:117-119`) — good. Partial lesson-ok/quiz-fail leaves sessionStorage; retry possible. No user-visible error.

#### 🟡 ADV-04 — Optimistic quiz score survives network failure

`saveQuizAttempt` updates React state **before** insert (`mutations.ts:72-83`). On error, toast only (`mutations.ts:92-93`). User sees a score the server does not have. Refresh "fixes" it; they may retake thinking it saved.

Lesson complete **does** roll back (`mutations.ts:51-55`). Asymmetric.

#### 🟡 ADV-05 — JWT expiry mid-lesson

Lesson pages are not middleware-guarded (`middleware.ts:84` dashboard only). Expired JWT → upsert error → rollback + generic `progress.saveError`. No "session expired, sign in" copy. `AuthProvider` still trusts `onAuthStateChange` session user (`AuthProvider.tsx:27-29`) until `getUser` completes (`:33-37`). Brief stale-signed-in window.

#### 🟡 ADV-06 — Contact duplicates / fail-open rate limit

`ContactClient` uses `submitting` flag only — double-click after await can double-post. No idempotency key. Live public INSERT makes this worse (ADV-10). Distributed limiter **fail-open** to in-memory (`rateLimitDistributed.ts:88-93`); cold start resets (`rateLimit.ts` comment + `:54`). #### 🟢 ADV-07 — `time_spent_seconds` is dead schema

Column exists (`002_lesson_progress.sql:7`). App never writes it (only mock + dashboard read `progress.ts:17,31-32,54`). Dashboard "minutes learned" is always 0. Product lie, not a crash.

### 5. Launch blockers (public embarrassment / harm to people seeking health info)

#### 🔴 ADV-08 — Privacy policy contradicts authenticated sync (public trust)

`src/messages/en.json:497-499` (and `es.json:497-499`):

> "We do not collect sensitive personal health information"  
> "We only store data locally on your device … **This data is never transmitted to our servers.**"

False for logged-in users: `lesson_progress`, `quiz_attempts` (including `answers` jsonb of chosen indices — `mutations.ts:84-91`, `003:8`), streaks, daily_log, notifications all go to Supabase. Quiz topics are health-literacy content (prescriptions, symptoms). GA `page_view` sends `/[locale]/learn/<slug>` (`analytics.ts:31-35`) — **lesson topic leakage to Google**. `trackEvent` is unused in prod (only tests) — dead API still forwards arbitrary props to gtag (`analytics.ts:40-48`).

**This is worse than a missing citation.** A journalist or privacy researcher will quote the policy against the network tab.

#### 🔴 ADV-09 — Account deletion is a placebo in production

`SettingsClient.tsx:75-89` → `rpc("delete_user")`. Function **not deployed**. `deleteError` → toast `deleteFailed`. JWT after successful delete: skill-known gap; client `signOut()` follows (`:87`). Moot until RPC exists.

#### 🔴 ADV-10 — Public INSERT on `contact_submissions` (live)

Policy still `WITH CHECK (true)` for `{public}`. Anon GRANT INSERT. Spam/PII dump; bypasses `isAllowedOrigin` (`contact/route.ts:25-66`), honeypot (`:86-90`), 5/10min limit (`:70-71`). **First-audit SEC-01 (missing service role env) is real for the Next route, but the table is already world-writable without that route.**

#### 🔴 ADV-11 — Password reset + email confirm (agree, still broken)

Re-read: `ResetPasswordClient.tsx:24-28` hash-only `code`. `confirm/route.ts:17` `searchParams.get("code")` only; no `token_hash`/`verifyOtp`. #### 🔴 ADV-12 — Care-guide copy reads as triage / treatment (misinformation risk)

Not just missing `sources` on articles (MED-01 — **agree**). Care guide **tells people what to do**:

- `en.json:613` `homeCareBody`: "Rest, fluids, and **over-the-counter medicine** for mild symptoms…"

`SignupForm.tsx:75-76`: `authError.message.includes("already registered")` → `errorEmailInUse`. Login/forgot-password are generic (**good**). Enumeration aids targeted phishing of a health-education audience.
